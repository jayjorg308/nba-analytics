# Usage rate is sourced descriptive context, never computed and never evaluation

The hero page's byline gains the season's **usage rate** — the NBA's official `USG_PCT`, the share of his team's possessions that end with the player's shot, drawn foul, or turnover while he is on the floor — as one more descriptive segment: `Cody Williams · 2025-26 · 18.4% usage · through Apr 12, 2026 · 72 games · vs league average`. The number is **presented, never computed**: the product pulls the NBA's reported value verbatim and recomputes nothing. It is descriptive context in the Matchup stance — sourced, formatted, never an evaluation input — and its vocabulary is reserved out of verdicts entirely.

**Why role context at all.** ADR-0064 declined archetype-adjusted selection but named the residual gap: the tool never tells the reader what is typical for a role. The reader meeting Cody's near-neutral selection has no way to know he is a bystander; meeting Shai's negative selection, no way to know he is the engine — and that context is load-bearing for reading the verdicts fairly. Attempt counts don't carry it (FGA ignores minutes, pace, and team context). Usage rate is the plainest single role signal and the one readers arrive already calibrated for.

**Why the official number, not our own math.** Conventional USG% embeds the 0.44 coefficient — permanently forbidden (the not-to-do list) — plus team on-floor context the product has no source for, so computing usage is off the table twice over. Presenting the NBA's own reported number is not computation; it is sourcing, attributed in the term popover. The turnover inclusion is definitionally correct for the concept the number names (turnovers end possessions), and *describing* a role is not *evaluating* it — the same line Matchup already walks. The shots-only alternative (`PCT_FGA`, share of team FGA while on the floor) was considered and declined: it has no public calibration, and it is blind to exactly the foul-drawing role THE LINE act taught us is scoring.

**The new class this creates, and its fences.** Every other number on the page traces to payloads the product derives and reconciles against oracles. `USG_PCT` is the first number the product presents but cannot verify — a sourced formula output, taken verbatim. Four fences keep it honest:

1. **Verbatim storage, presentation formatting** (ADR-0011's split): `_meta` carries the value exactly as the API returns it — a fraction, API-rounded to three decimals (spike-recorded: Cody 0.159, Shai 0.323); `src/format.ts` renders `15.9% usage` at one decimal, the NBA's own display convention, so our number is recognizably *their* number.
2. **The FGA oracle** — the one checkable fact. The design's first draft asserted the Advanced row's games-played equals the payload's `gamesIncluded`; the build's spike falsified that on the launch hero (Cody: GP 67 vs 62 shot-record games — five appearances with zero field-goal attempts, which a low-usage wing legitimately has; GP counts games *played*, `gamesIncluded` games *with a shot*). The checkable fact is FGA, which the Advanced row also carries: the derive hard-fails unless the row's FGA equals the payload's pre-drop season FGA (`totalShots + zoneConflictsDropped`) — the same identity the sibling contracts reconcile on, and strictly stronger than GP would have been (a stale or mis-anchored artifact fails FGA equality exactly; GP ≥ `gamesIncluded` rides along only as a corruption sanity check, never as equality). That is what makes the byline one coherent claim: the usage figure and the stated frontier describe the same season-to-date record.
3. **Full frontier participation.** On a living season the league Advanced pull is frontier-anchored (`DateTo`, the same endpoint as the totals pull; the spike proved the Advanced measure respects `DateTo` — rows, GP, and `USG_PCT` all move with the date for all five heroes), and a lagging Advanced dashboard defers the day's publish like any other source — lag defers, contradiction halts, no tolerances (ADR-0058). Descriptive color can now hold up a data commit; the alternative (usage floating on its own as-of date) would put two dates in one byline.
4. **No computed league anchor, ever.** A league-average `USG_PCT` would be a rate average (ADR-0004's prohibition) over components the product must not touch. The only honest calibration is definitional — five players share the floor, so an even share is 20 percent — and that is structural copy, which lives in the term popover, never as data beside the number.

**Contract and sourcing.** Shot payload `_meta` bumps to v5: required `usagePct` (verbatim) plus `usageSourceSnapshot` (the payload stays self-describing; the replay proof's provenance-exempt field list grows by one). Shot golden regenerated; the three sibling goldens stay byte-stable. Every registered hero-season re-derives and re-syncs in the same PR — the schema bump makes that mandatory anyway. The source is one league-wide artifact per season, `data/raw/_league/<season>/advanced/<pull-date>.json`, a sibling class beside the totals artifact; `pull_league_totals.py` writes both in one run, each with its own append-only guard, so `hero:add` and the season loop keep one league-pull step.

**Placement and vocabulary.** The byline is usage's one home — the identity register, read before the evidence starts — between the season and the frontier. Never near the headline decomposition: proximity there would read as a fourth number in the argument, which is precisely the muddying this feature was interrogated for. "Usage" is Term-wrapped in the byline (its first reading-order mention; the byline joins ADR-0052's wrapped surfaces), and the popover carries the definition, the attribution, and the even-share calibration. In the verdict lexicon, "usage" enters the **reserved list**: forbidden in verdicts regardless of claims, with no UsageClaim kind defined. Graduation requires its own ADR defining the claim kind before any prose (the growth pattern), and is plausible only for the ADR-0064 revisit case — a hero whose story genuinely turns on role.

**What must not regress:** never compute usage or any usage component (the 0.44 stays forbidden in every form); never render usage near the decomposition or feed it to any evaluation; never place a computed league-usage anchor beside the number; the FGA oracle never loosens; a verdict never says "usage" without a prior graduation ADR; and the number is never re-graded (ADR-0064's rail — role context describes, the absolute benchmark judges).
