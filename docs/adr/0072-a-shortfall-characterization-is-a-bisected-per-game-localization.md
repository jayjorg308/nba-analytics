# A shortfall characterization is a bisected per-game localization

ADR-0030's amendment set the bar a tracking-shortfall pin must clear — "a characterized outage, never 'the derive said so'" — and ADR-0058's amendment made pins move only by PR, with the season loop's stuck-frontier alarm as the system's way of asking a human for one. Neither ADR said what a characterization **is**. This one does: a pin is earned by **localizing the season gap to specific games with bisected `DateTo`-anchored tracking pulls**, and by nothing weaker. The tool is `ingestion/localize_shortfall.py`; the standing definition lands in CONTEXT.md's Tracking shortfall entry and `season.config.json`'s `_readme`.

**The mechanism.** The tracking dashboards are season-aggregate — no GAME_ID exists anywhere in a `playerdashptshots` response — so per-game attribution cannot be read off any snapshot. But the endpoint respects `DateTo` (the ADR-0058 spike's finding, the same mechanics the coherence check runs on), so the cumulative shortfall through date X — official pre-drop FGA through X minus the tracking General family's Σ FGA through X — is a **non-decreasing step function over the hero's game dates**. Every step is one outage game; bisection finds each in ~log2(games) pulls. The 2026-08-10 characterizations ran 7 pulls over Sarr's 48 games and 8 over Carrington's 82, against 48 + 82 for the linear alternative. Official cumulative FGA comes from the committed raw shot snapshot's per-shot rows; the target is the pre-drop total, the same denominator the General identity is stated against.

**The fingerprint that confirms an outage.** At each localized game, the per-family delta across the anchored snapshot pair brackets the game exactly: every tracking family (General, Shot Clock, Closest Defender, Dribble, Touch Time) short by the **same** count is a tracking-side gap in the optical record — a missing segment hits all derived views identically. A family-specific discrepancy would be corruption instead (a family disagreeing with its own universe hard-fails, ADR-0030), and a negative step is contradiction, never outage. Both 2026-08-10 games carried the clean fingerprint: Carrington's `0022500029` (2025-11-07), every family short by exactly 1 of his 12 attempts; Sarr's `0022500938` (2026-03-10), every family short by exactly 6 of his 19.

**Why circumstance is banned: the method falsified it on first contact.** The day before the bisection existed, Carrington's 1-attempt shortfall was pinned to `0022500900` — the 2026-03-05 league-wide meltdown night already characterized for Ace Bailey — on the reasoning that it was the only characterized-outage game he had played. Plausible, evidence-adjacent, and **wrong**: the bisection put his missing attempt on 2025-11-07, a night no existing pin covered (and it also surfaced that he had played the newly discovered Sarr outage game, so the "only candidate" premise was false twice over). A circumstantial pin fails silently in the worst way — the guard's season-sum assertion passes on a wrong per-game attribution, and the error only detonates later, at a mid-season frontier where the coherence check needs the per-game grain to be *true* (a wrong-date pin explains a gap it shouldn't or misses one it should, and the loop retreats or halts on clean data). **Proximity to a characterized outage is not characterization.**

**Mechanics that must hold.** Investigation snapshots land in `tracking/investigation/`, a subdirectory on purpose: `derive_creation` treats the lexicographically last `*.json` in the flat `tracking/` dir as the latest real snapshot, so a stamped investigation file there would silently become every later derive's input. Existing investigation snapshots are reused instead of re-pulled — append-only holds (ADR-0006), reruns are free, and a teammate's overlapping night costs nothing. The tool prints the pin candidate and **never writes the config**: the pin still travels by PR with its evidence recorded in the `_readme` (ADR-0058), and the localization is the evidence. Pulls are local-only like every pull.

**Consequences:** the stuck-frontier alarm now has a standing answer — run the localization, review the fingerprint, pin by PR — instead of an unwritten investigation each time. A future contributor must not pin a shortfall by co-occurrence with a known outage night, must not accept a localization whose steps fail to sum to the season shortfall, must not land investigation snapshots in the flat `tracking/` directory, and must not teach the season loop to run this tool — the loop asks for a characterization by halting; producing one stays human-initiated (ADR-0058's boundary).
