# The standing add recipe is one resumable command

The hero-add recipe that four manual adds refined and ADR-0063 partially mechanized is now a single orchestrated command: `npm run hero:add -- "<Player Name>" <season>` (`ingestion/hero_add.py`) chains, in dependency order, the three raw pulls (shots; tracking, with the league baseline only when the season lacks one; the Gate 5 league-totals artifact), the shot-payload derive, completion of the shared play-by-play corpus, the three sibling derives, the season-argument scaffold, the ADR-0065 headshot fetch, the four-payload `hero:sync`, and a closing `hero:report --deployed`. Input is a player name and a season; every identity downstream — the slug, the player id, the game list — is read from the artifacts themselves, never typed twice (the ADR-0063 stance, extended from the scaffold to the whole chain).

**Resumable by construction, not by checkpoint.** No run state is kept; each step's own storage semantics make a rerun safe. Append-only pulls skip when their snapshot exists; the corpus step diffs the season's game ids against the shared corpus and requests only the missing pairs — `pull_play_by_play --game-ids`, the "pre-deploy hero-add path" that flag always anticipated, behind the corpus's own half-pair orphan halt; derives recompute freely (the regenerable layer); the scaffold is skipped once its guard file exists, the headshot once committed. A failed run's remedy is always "fix the cause and rerun" — there is nothing to clean up.

**The ADR-0063 boundary is unchanged: automation widened to acquisition, never to judgment.** On success the command leaves the suite red on the authoring tripwire, and its closing checklist names exactly the human work — the banner photo and its credit, the verdict/kicker/alt/focal points, the claim declarations, the optional team mark. What it newly automates is mechanical by ADR-0065's own argument: the headshot "asset is a formula," so the tool now executes the formula instead of quoting it in a scaffold comment.

**Scope:** completed seasons only. A living season is acquired and published by the season loop (ADR-0057/0058); this command never touches `season.config.json`, canonical pointers, or any flip bookkeeping. Local-only like every pull (stats.nba.com blocks cloud IPs) — never CI or the deployed app.

**A source characteristic, recorded:** cdn.nba.com (the headshot CDN) hangs non-browser TLS fingerprints — python-requests read-times-out on every attempt while curl fetches the same URL immediately (observed 2026-07-27). The headshot fetch is therefore curl-first (system curl, browser UA and referer) with a python-requests fallback. Any future asset fetch from an nba.com CDN — the per-hero social cards are the obvious candidate — should expect the same behavior.

**First proof:** the fifth hero add ran through it the day it was built — Donovan Mitchell 2025-26: 67 new corpus game pairs, all five gates pass, all four payloads derived, reconciled, and deployed; two mid-run failures (both the CDN characteristic above) resumed cleanly with zero re-pulled artifacts.
