# The game payload is one immutable file per game, with both teams

Every team game publishes as one committed file, `public/data/_teams/<tricode>/<season>/games/<gameId>.json`, carrying everything a report card and a player's night read, for **both** teams, the subject team first. A side is the team's identity and box team line, the box line of every player who appeared (with the technical and split free throws the trip grammar counted for him), the shot rows (the hero contract's enriched row plus `playerId` and `assistStatus`, post-drop, chronological), the zone-point conflicts the drop removed, listed so a receipt can strike them (ADR-0019), and the trips (the ADR-0053 v3 trip row plus `playerId`). `_meta` carries the game's identity, the opponent, home, the ruler (ADR-0089), and the game's pbp/box pair; `zoneBaseline` is the ruler rolled up, so each file is self-contained, the house pattern. A living **season index**, `<season>/index.json`, lists every published game: slug, date, opponent, home, both scores, the subject's box team line, and that game's ruler with its rolled-up zones. It supersedes the game-log contract (ADR-0086) for the product and will replace the ledger facts file (ADR-0084) when the season page reads it; until then the ledger stays exported beside it.

**Why both teams in one file.** The report card answers "what did the other side take, on the same terms?", so the opponent is priced by the same function, against the same ruler, in the same file. The opponent's shots come from one extra call per game, a team-wide `shotchartdetail` windowed to the game's date (`live_pulls.pull_team_game_snapshot`), loaded into the existing `shot` table at natural identity like every other team pull, with the window's one-day league frame never loaded anywhere (it is that day's league only). Box lines, trips, and assist statuses for both sides come from the game's pbp/box pair, which is already required.

**Born DB-native.** `ingestion/export_game_payload.py` reads the record store and runs the derive grammars as libraries over stored events: trips, technicals, and splits by `derive_freethrow.reconstruct_game_trips` per player, assist statuses by `derive_shot_context.parse_actions` and `classify_rows`, the matchup by the team payload's own enrichment. No file derive exists, and no table holds the opponent's trips: the grammar runs at export, so a bench player who will never be a hero is reconstructed exactly like a hero. Oracles, all hard-failing at export and re-asserted at the TypeScript load boundary: per player per side, pre-drop rows equal box FGA; trips plus technicals plus splits equal the box free-throw line; made field-goal points (priced, heaves, and conflicts) plus every free-throw point equal box points; per side, the players sum to the box team line, and assist statuses bound the official team assists (assisted at most the box total, the box total at most assisted plus unknown makes) after the grammar's own exact reconciliation of parsed credits (ADR-0046); the subject's shots equal the team shot payload's slice for the game, field for field and in order; and the ruler is the recorded frame for its date, complete in every evaluation zone. A deployed-pair guard re-asserts the slice, the index, and the ruler against the committed files.

**Immutable once published.** The export writes a game file once: identical bytes are a no-op, and different bytes over a published file refuse. A later source change to a published game is first a changed row at load, which halts (ADR-0080); a human decides whether it is a correction, and a correction travels by PR with a note (`--allow-rewrite`). Immutability is what lets a shared card mean the same thing next month, and what lets the quadrant compare games across a season and across seasons without a moving baseline.

**Why the index carries rulers but not per-game metrics.** The quadrant and the season views need every game's two numbers. Each is `aggregateShotMetrics` over that game's slice of the team shot payload under that game's ruler (ADR-0009), so the index carries the ruler pairs and the browser computes; a dot can never disagree with its card, because both are the same function over the same rows and the same pairs. The index does not repeat the roster, which stays in the team shot payload.

**Golden and tests.** The golden is a truncated two-team fixture of one real game (0022500492, the 2025-26 Jazz at Golden State, holding the season's one zone conflict, technicals on both sides, and-ones, a bonus trip, and a shotless free-throw trip), generated through the record-store path by `ingestion/regen_game_golden.py`, never `golden:regen`. Every oracle has a manufactured-violation test, and so does immutability.

**Consequences.** Opening night needs no page work: raw is append-only and every game file rebuilds from it. A season of game files is about 10 MB committed (2025-26: 82 files), the price of static serving and URL reproducibility (ADR-0086's reasoning). Phase 4's league-wide pulls make the per-game opponent call redundant without changing this contract. A future contributor must not persist per-game metrics, must not rewrite a published game file outside a reviewed correction, and must not price the two sides against different rulers.

**Amendment (2026-10-15, ADR-0091) — the subject's side reads its own one-day pull too.** The season pull is a source head that moves with every session's pull, so a game file naming it would change the next morning and refuse. Live seasons therefore source both sides from one-day pulls of the game, one more call per game; the export's preference for a side's one-day pull, when loaded, already named it. The season loop exports into `data/derived` and checks each game against its published file (`export_season`'s `published_dir`). The committed 2025-26 files, built from one scratch load, name the season pull and stay as they are.

**Amendment (2026-10-29, the index's player lines):** the season index moves to schema v2 for the player season page (ADR-0095): each game row gains `players`, the box line of every subject player who appeared, which is the game file's own line less the technical and split free-throw counts. The load boundary re-asserts that the players sum to the box team line on the fields the game payload sums (points, field goals, threes, free throws; never assists), and the deployed guard holds every row's lines equal to its game file's. Game files are untouched: the 2025-26 re-export through the scratch store wrote 0 and left 82 unchanged, and the 2026-27 export from the production store matched its five published files.
